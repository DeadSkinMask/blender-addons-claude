# Blender → Godot MultiMesh scatter exporter

Exports Geometry Nodes instances from Blender 5.2 and rebuilds them in Godot 4.7 as a single `MultiMeshInstance3D`.

| File | Runs in | Purpose |
|---|---|---|
| `godot_multimesh_scatter.py` | Blender 5.2 | Add-on: exports the instance mesh (GLB and/or OBJ) and the instance transforms (`.bin`). |
| `GodotScatterBinaryLoader.gd` | Godot 4.7 (4.4+ required) | `@tool` node: loads the mesh + `.bin` and builds the MultiMesh, with an editor preview. |

## Output format

The add-on writes to the output folder:
- `scatter_mesh.glb` and/or `scatter_mesh.obj` (+ `scatter_mesh.mtl`): the source mesh used by the Geometry Nodes `Object` input.
- `scatter_transforms.bin`: compact little-endian binary with an 8-byte header (`GMMI0001`), a uint32 instance count, then 12 float32 values per instance (basis X column, Y column, Z column, origin), already converted to Godot's Y-up space.

A `.res` is not a good interchange format here: Godot's serialized resources are engine-version-specific and Blender cannot write a valid native Godot resource directly. GLB/OBJ + a small binary file is portable, compact, and fast to parse.

### GLB or OBJ?

| | GLB | OBJ |
|---|---|---|
| Godot import result | `PackedScene` (mesh is taken from the first `MeshInstance3D`) | `Mesh` by default, or `PackedScene` if imported "as Scene" |
| Source object transform | Kept as a node transform, ignored by the loader | **Baked into the vertices** |
| Materials | PBR materials embedded | Basic `.mtl` materials |

Either works with the loader. With OBJ, keep the source mesh at an identity transform (see limitations), otherwise its transform is applied on top of every instance.

## Blender setup

1. Blender: Edit → Preferences → Add-ons → dropdown → **Install from Disk**; select `godot_multimesh_scatter.py` and enable it.
2. Switch to **Object Mode**. The export button is disabled in any other mode (hover it to see the reason) and the panel shows a warning.
3. In the 3D View, open the sidebar with `N`, then the **Godot** tab.
4. Select the object that owns the Geometry Nodes modifier (the scatter host). It must be the active object.
5. Set **Output folder** to a folder inside the Godot project (for example `D:\project\assets\scatter\`).
6. Set **Instance mesh** to the same mesh object connected to the node group's `Object` input.
7. Keep **Relative to host** enabled if the Godot loader node will be placed at the scatter host's location. Disable it to export world-space transforms.
8. Keep **Export mesh** enabled and choose **Mesh format**: `GLB`, `OBJ` or `GLB + OBJ`. Disable **Export mesh** to re-export only the transforms.
9. Click **Export to Godot**.

The exporter reads dependency-graph instances generated by the evaluated Geometry Nodes host. The output geometry must still be instanced at the group output; if the graph realizes instances, they no longer appear as separate dependency-graph instances and the export is cancelled with an error.

## Godot setup

1. Copy `GodotScatterBinaryLoader.gd` into the project.
2. Let Godot import the generated mesh file (`.glb` or `.obj`). `scatter_transforms.bin` is not a resource and needs no import.
3. Add a `Node3D`, attach the script, and set:
   - **Mesh Scene Path** → `res://.../scatter_mesh.glb` or `res://.../scatter_mesh.obj` (`.gltf`, `.tscn`, `.scn`, `.res`, `.tres` and `.mesh` are also accepted).
   - **Transforms Path** → `res://.../scatter_transforms.bin`.
4. Click **Rebuild** in the inspector (or reopen the scene). A child `ScatterMultiMesh` node is created and saved with the scene.
5. If Blender exported host-relative transforms, position the loader node at the equivalent host transform in Godot (normally the host origin; avoid applying the host transform twice).

After re-exporting from Blender, just click **Rebuild** again; the previous `ScatterMultiMesh` is replaced, never duplicated.

### Inspector properties

| Property | Description |
|---|---|
| `Mesh Scene Path` | Mesh source: GLB/glTF/OBJ or a saved scene/mesh resource. |
| `Transforms Path` | The `.bin` written by Blender. |
| `Rebuild On Ready` | Rebuild automatically when the node enters the tree (editor and game). |
| `Use Custom AABB` / `Custom AABB` | Override the MultiMesh culling box. |
| `Override Material` | Replaces every surface material of the mesh on all instances. Applied live; leave empty to keep the imported materials. |
| `Rebuild` (button) | Reloads the `.bin` and the mesh. |

**Debug preview** group (drawn as an internal node: not shown in the scene tree and never saved):

| Property | Description |
|---|---|
| `Debug Preview` | `None`, `Points` (one point per instance origin), `Bounds` (box enclosing all instances, including their rotation/scale) or `Points And Bounds`. Default: `None`. |
| `Debug Color` | Preview color; alpha < 1 makes it translucent. |
| `Debug Point Size` | Point size in screen pixels (does not scale with distance). |
| `Debug On Top` | Draw through other geometry (off by default). |
| `Debug In Game` | Also show the preview when running the game (editor only by default). |

### Exporting the game

Godot does not pack non-resource files by default. In **Project → Export → (preset) → Resources → Filters to export non-resource files/folders**, add `*.bin`; otherwise `scatter_transforms.bin` is missing from the build and the loader fails to open it.

## Coordinate convention

The exporter uses the conventional Blender-to-Godot mapping `(x, y, z) → (x, z, -y)`: Blender Z-up becomes Godot Y-up, and Blender's -Y forward maps to Godot's -Z forward. Both translation and basis vectors are converted (`C · M · C⁻¹`). The OBJ exporter is configured to match (`up_axis='Y'`, `forward_axis='NEGATIVE_Z'`), as is the GLB exporter (`export_yup=True`). If your project intentionally uses a different convention, change `blender_to_godot_matrix` and the exporter axes consistently.

## Important limitations / validation

- One source mesh for all instances, which is exactly what `MultiMeshInstance3D` requires. Use separate MultiMesh nodes/files for different source meshes.
- Test with a tiny scatter (3–10 instances) first. Confirm the source mesh's local origin, orientation and scale are suitable.
- Keep the source mesh object at an identity transform: apply it with **Ctrl+A → All Transforms**. This is required for OBJ (transform baked into vertices) and recommended for GLB.
- The exporter does not export per-instance colors, materials, mesh variants, or custom attributes. Shaders that read `COLOR` / `INSTANCE_CUSTOM` get no per-instance data.
- Geometry Nodes dependency-graph instance exposure can vary with graph structure and Blender version. If no instances are found, the add-on reports an error rather than exporting an empty file.
- The mesh exporters change the selection; the add-on restores the scatter host as the active, selected object afterwards.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `ReferenceError: StructRNA of type DepsgraphObjectInstance has been removed` | Fixed in the current version: instance matrices are copied while iterating the depsgraph. Update the add-on. |
| Export button greyed out | Not in Object Mode. |
| "No dependency-graph instances found" | The active object is not the scatter host, or the node tree realizes instances before the output. |
| "No Mesh found in: …" in Godot | Wrong `Mesh Scene Path`, or the mesh has not finished importing. |
| "Scatter file is truncated" / "Invalid scatter binary header" | The `.bin` is incomplete or not from this add-on; re-export. |
| Instances offset/doubled in position | Host transform applied twice (`Relative to host` vs. loader node placement) or unapplied source-mesh transform (OBJ). |
| Works in editor, fails in exported game | `*.bin` not included in the export filters. |
| `No support for Typed UAV Load Additional Formats` / "switching to Vulkan" on Run | Not related to this tool: the GPU/driver lacks the Direct3D 12 features Godot needs, so Godot falls back to Vulkan (harmless). To silence it, set **Project Settings → Rendering → Rendering Device → Driver.windows** to `vulkan`, or update the GPU driver / force the dedicated GPU for Godot in Windows graphics settings. |
